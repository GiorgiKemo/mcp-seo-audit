## Assessment

The audit identifies several real problems, especially external redirects being reported as fetch failures, misleading robots inspection, missed HTTP `Link` headers, and lease-loss handling. But it also presents intended behavior and unsupported assumptions as defects. I would **not apply the proposed fixes wholesale**: several would change correct Google-compatible behavior or weaken rendering safeguards.

The highest-confidence priorities are **#4, #14, #15 and #11**, followed by report-comparison accuracy (#10). The renderer claim (#5) needs a real browser reproduction before its severity can be assessed.

## Additional blind spots

1. **Canonical elements outside `<head>` can suppress a missing-canonical finding.** [gsc_server.py](/Users/nita/.gemini/antigravity/scratch/mcp-seo-audit/gsc_server.py:710) searches all `<link>` elements, while Google accepts the HTML canonical element in the document head. A body-only canonical can therefore be treated as valid. Restrict the Google-facing check to the head and flag misplaced declarations separately. [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

2. **The crawl time budget does not bound the initial robots fetch.** The deadline is created before `_load_crawl_robots`, but that call is not enclosed in the remaining deadline; the sitemap and page fetches are. Slow responses or redirects can therefore make a requested short `max_seconds` run exceed its stated crawl budget. Apply the remaining deadline to robots loading and preserve an explicit incomplete-coverage reason. [gsc_server.py](/Users/nita/.gemini/antigravity/scratch/mcp-seo-audit/gsc_server.py:2535).

3. **Robots redirects can change the policy’s origin without disclosure.** `_load_crawl_robots` follows redirects without a same-origin validator, then constructs the original origin’s policy from the final response. Redirect support may be intentional, but the report should retain the final URL and redirect evidence so the policy’s source is inspectable; test cross-origin redirects and failed hops explicitly. [gsc_server.py](/Users/nita/.gemini/antigravity/scratch/mcp-seo-audit/gsc_server.py:2509).

## Patch order

1. **Reliability and truthful classifications:** #14 lease fencing/error handling, #4 redirect classification, and the unbounded initial robots fetch. Add tests for expiry/preemption, rejected redirect destinations, and deadline exhaustion.
2. **SEO result correctness:** #15 robots inspection, #11 HTTP headers plus non-HTML handling, the misplaced canonical blind spot, and #10 stable finding identities.
3. **Operational and evidence improvements:** #9 failed canonical observations, #12 project lifecycle, and #13 retry policy. Decide behavior before implementing.
4. **Investigate before changing:** browser reproduction for #5; validator evidence for #6 and #8; optional compatibility and usability work for #7, #16–19 and #21.
